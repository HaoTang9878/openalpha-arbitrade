## 二、币种扩展方案

### 扩展原则
1. 优先选择**跨所价差较大**的小市值币种（流动性低 = 价差大）
2. 覆盖**多赛道**分散风险（主流/DeFi/Layer2/AI/RWA/Meme/新公链）
3. 确保至少 **4 个主流交易所**都支持（避免单所孤立）
4. 单笔下单量按币种价格**分级配置**（高价币小量、低价币大量）

### 扩展后币种清单（40 个）

| 分类 | 币种 | 数量 | 单笔下单量(基础币) |
|------|------|------|-------------------|
| 主流币 | BTC/ETH/SOL/BNB/XRP | 5 | 0.001-0.1 |
| DeFi | DOGE/AVAX/ARB/OP/LINK/UNI/AAVE/MKR/CRV/SNX | 10 | 0.5-5 |
| Layer2 | MATIC/STRK/BLUR | 3 | 2-10 |
| AI | FET/AGIX/RNDR/TAO | 4 | 1-5 |
| RWA | ONDO/PENDLE | 2 | 2-10 |
| 新公链 | SUI/SEI/TIA/INJ/APT/NEAR/ATOM/DOT | 8 | 0.5-5 |
| Meme | PEPE/WIF/BONK/FLOKI/SHIB | 5 | 1000-100000 |
| 稳定币生态 | LDO/ENA | 2 | 2-10 |
| 交易所平台币 | GT/CRO | 1 | 2-10 |

### 下单量分级配置

```python
# 按价格区间自动配置下单量（USDT 名义价值约 50-100）

    "high":   {"max_price": 999999, "amount": 0.001},   # BTC/ETH 等
    "mid":    {"max_price": 100,     "amount": 0.1},     # SOL/BNB/LINK 等
    "low":    {"max_price": 10,      "amount": 5},       # DOGE/ARB/OP 等
    "micro":  {"max_price": 1,       "amount": 50},      # PEPE/SHIB 等
    "nano":   {"max_price": 0.1,     "amount": 1000},    # BONK/FLOKI 等
}
```

### P0 致命问题

| # | 问题 | 排查方法 | 修复方案 |
|---|------|---------|---------|
| 1 | 自动套利未启动 | `curl /api/status` 看 `arbitrage_running` | 调用 `/api/arbitrage/start` |

## 五、每日记录流程

### 自动记录（服务器 cron）

```bash
# 每小时抓取一次机会快照
0 * * * * cd /root/openalpha-arbitrage && python3 scripts/daily_record.py >> data/logs/daily_record.log 2>&1

# 每日 23:55 生成当日报告
55 23 * * * cd /root/openalpha-arbitrage && python3 scripts/daily_report.py >> data/logs/daily_report.log 2>&1
```

### 记录内容

1. **每小时机会快照**：时间戳 + 所有机会（交易对/交易所对/价差/净利润率/风险）
2. **每日报告**：
   - 当日检测到的机会总数、唯一交易对数、唯一交易所对数
   - 价差分布（<0.1% / 0.1-0.5% / 0.5-1% / >1% 的占比）
   - Top 10 最大价差机会
   - 模拟交易执行数、盈亏汇总、胜率
   - 交易所连接稳定性（平均延迟、断连次数）
   - 发现的问题与改进建议

### 报告存储

- `data/reports/YYYY-MM-DD.md` — 每日 Markdown 报告
- `data/snapshots/YYYY-MM-DD.csv` — 每小时机会快照 CSV
- `data/arbitrage.db` — 结构化数据（trades + opportunities 表）
